# Gitignored OTA Public Key Design Specification

- **Date:** 2026-10-24
- **Status:** Approved
- **Target Applications:** Intercom Bridge (`intercom-matter`) & HVAC Bridge (`hvac-bridge`)
- **Key Type:** Ed25519 32-byte Verifying (Public) Key

---

## 1. Executive Summary

Both `intercom-matter` and `hvac-bridge` use Ed25519 digital signatures to verify OTA firmware updates before flashing. Previously, the 32-byte public key `OTA_PUBLIC_KEY` was hardcoded directly in `crates/<app>-firmware/src/config.rs` and committed to git.

This specification decouples the cryptographic verification key from the committed source code by reading the public key from a gitignored binary file (`ota_public_key.bin`) at compile time via Rust's `*include_bytes!()` macro, while automating key extraction directly from the local private keys (`~/.intercom/ota_key.pem` and `~/.hvac/ota_key.pem`) via `scripts/generate_keys.py`.

---

## 2. Architecture & File Layout

### 2.1 Key File Location
The raw 32-byte Ed25519 public key file will reside in each firmware crate's root directory:
- `crates/intercom-firmware/ota_public_key.bin`
- `crates/hvac-firmware/ota_public_key.bin`

### 2.2 Gitignore Enforcement
- In `intercom-matter/.gitignore`: Add `ota_public_key.bin`.
- In `hvac-bridge/.gitignore`: Add `ota_public_key.bin` explicitly.

These files will not be tracked or committed to version control.

### 2.3 Key Generation & Extraction (`scripts/generate_keys.py`)
`scripts/generate_keys.py` in both repositories will:
1. Ensure the user's private key directory exists (`~/.intercom` or `~/.hvac`).
2. Generate a new `ota_key.pem` if one does not exist (with `0600` permissions), or load the existing private key.
3. Extract the 32 raw bytes of the corresponding Ed25519 public key.
4. Automatically write the raw bytes to `crates/<app>-firmware/ota_public_key.bin`.
5. Print status confirming the path of the generated private key and the output binary public key.

---

## 3. Firmware Compile-Time Loading

In both `crates/intercom-firmware/src/config.rs` and `crates/hvac-firmware/src/config.rs`:

```rust
/// Ed25519 public key used to verify incoming OTA firmware images.
/// Loaded at compile time from the gitignored `ota_public_key.bin` file.
pub const OTA_PUBLIC_KEY: [u8; 32] = *include_bytes!("../ota_public_key.bin");
```

Because `include_bytes!` resolves paths relative to the source file where the macro is invoked (`src/config.rs`), `../ota_public_key.bin` resolves to `crates/<app>-firmware/ota_public_key.bin`.

At compile time:
- The compiler loads exactly 32 bytes into static read-only memory.
- If `ota_public_key.bin` is missing, the Rust compiler fails with a clear compile error indicating the file is missing, directing the developer to run `python3 scripts/generate_keys.py`.
